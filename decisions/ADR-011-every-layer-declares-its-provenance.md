# ADR-011 — Every layer declares its provenance

**Date:** 2026-05 · **Status:** Accepted

## Context

The habitat-suitability pipeline assembles **38 raster layers from five independent
sources** — a global surface-water product, bioclimatic variables, soil properties,
vegetation indices reduced over several years, and an elevation model with terrain
derivatives. Some arrive through Google Earth Engine, one through a web coverage service.

Every one of them has attributes that change the meaning of any result computed from it:

- **A version.** These products are revised. A surface-water dataset at version 1.4 is not
  the same data as version 1.3, and a result computed from one is not reproducible from
  the other.
- **A native resolution**, which is rarely the nominal one quoted in the documentation, and
  which determines what a zonal statistic actually averages.
- **A band**, since one product ships several and they mean different things.
- **A temporal reduction**, where a multi-year series was collapsed to a single layer — over
  which years, and by what reduction.
- **A spatial extent**, which is a study-design decision, not a technical detail.

The normal practice is that these live in the methods section of a manuscript, written
months later, abbreviated for length, and reconstructed from memory. The result is a study
nobody can rebuild — including its author, two years on.

The failure is quiet. A layer silently updated upstream, or a resolution assumed rather
than recorded, produces a different answer with no indication that anything changed.

## Decision

**The download step emits a machine-readable manifest describing every layer it fetched,
and the manifest ships with the data.**

Per layer: source identifier, version, band, output filename and path, nominal resolution,
and the actual native resolution in degrees. Per run: a UTC timestamp, the coordinate
reference system, the bounding box, and a count of layers grouped by source.

Two details make it more than a file listing.

**The bounding box records where it came from.** Not just four numbers — a note stating
that the extent derives from the coordinates given in a 1969 taxonomic description, plus a
stated buffer. That is a study-design decision with a citation, recorded next to the
numbers it produced, rather than left as an unexplained rectangle.

**Native resolution is recorded alongside nominal resolution.** A product described as
30 m is stored in degrees at a value that is only approximately 30 m, and varies with
latitude. Recording both means a later reader can tell what a zonal average actually
averaged.

The manifest is generated by the code that does the download, so it cannot describe
something other than what was fetched.

## Consequences

**What was gained**

- The stack is rebuildable years later, at the versions actually used.
- A methods section is written *from* the manifest instead of from memory, and cannot
  quietly disagree with the data.
- An upstream version change becomes visible instead of silent.
- Reviewers can check the data provenance without asking.
- It composes with the QC record: manifest says what was fetched, QC says whether it was
  usable.

**What it cost**

- **The manifest is a snapshot, not a guarantee.** It records the version fetched; it
  cannot make the provider keep serving it. A withdrawn dataset is still unrecoverable,
  and the manifest only tells you what you lost.
- **Nothing verifies the manifest against the files.** A layer deleted or replaced by hand
  afterwards leaves the manifest describing something that is no longer there — the same
  unverified-coupling gap that
  [ADR-010](ADR-010-verify-the-citations.md) closed for citations, still open here. A
  checksum per layer would close it and is the obvious next step.
- **It captures acquisition, not transformation.** Reprojections, resamplings and derived
  variables computed downstream are not in the manifest, so it documents the inputs rather
  than the full lineage.
- **More code in the download path**, which must itself stay correct.

The generalisable principle: **data without provenance is an anecdote.** The same reasoning
that makes an accuracy claim require independent check points
([ADR-001](ADR-001-validation-with-independent-check-points.md)) makes a derived result
require a record of exactly what it was derived from. In both cases the work is
front-loaded and the payoff arrives when somebody — often you — asks a question the
original run did not anticipate.
